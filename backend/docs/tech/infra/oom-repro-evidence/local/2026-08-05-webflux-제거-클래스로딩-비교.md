# WebClient→RestClient 전환 전/후 클래스 로딩 비교 (2026-08-05)

## 배경

`2026-08-04-운영-힙논힙-실측.md`(`../production/`)에서 논힙(Metaspace)이 힙보다 크고
`MaxMetaspaceSize`가 무제한이라 OOM의 실질적 원인임을 확인했다. 원인 조사 결과, 카카오
로컬/인증 API 클라이언트 5곳이 전부 `WebClient`를 `.block()`으로 동기 호출만 하고
있었는데도 서버가 필요로 하지 않는 Reactor Netty 스택 전체가 로드되고 있었다. 이를
Spring Boot 내장 `RestClient`로 교체하고 `spring-boot-starter-webflux` 의존성을
제거했는데(관련 커밋: `refactor: WebClient를 RestClient로 전환하고
spring-boot-starter-webflux 제거`), 이 실험은 그 효과를 "추측"이 아니라 같은 조건에서
직접 비교해 수치로 확정하기 위한 것이다.

## 실험 조건

- **비교 대상**: `spring-boot-starter-webflux` 제거 커밋 직전(`HEAD~2`,
  `3d5963d9`)과 제거 후(현재 브랜치 HEAD)를 각각 별도 `git worktree`로 체크아웃해
  독립된 JVM 프로세스로 기동.
- **환경**: 로컬 `docker-compose.local.yml`(MySQL 3307, Redis 6380), `bootRun`으로
  네이티브 기동. 두 버전 모두 동일한 `.env.local` 기반 환경변수(DB/Redis/Kakao/Firebase)
  사용.
- **측정 시점**: `Started CapstoneApplication` 로그 직후 — 부팅만 끝나고 외부 API
  호출(카카오 검색 등)은 발생하지 않은 idle 상태. 트래픽 없이 잰 스냅샷이라는 점에서
  운영 실측 문서와 동일한 한계를 공유한다(아래 "남은 공백" 참고).
- **측정 도구**: `jcmd <pid> VM.metaspace`(논힙 총량), `jcmd <pid> VM.classes`(로드된
  전체 클래스 목록을 텍스트로 덤프한 뒤 패키지별로 grep 집계).
- **firebase-admin 자격증명**: 별도 worktree에는 gitignore된 서비스 계정 JSON이 없어
  최초 시도가 `FileNotFoundException`으로 실패했다 — 자격증명 파일을 복제하지 않고
  `FIREBASE_CREDENTIALS_PATH` 환경변수를 원본 워크트리의 절대경로로 지정해 재시도했다.

## 핵심 발견 — Netty 460개 중 절반 이상이 webflux 몫이었다

로드된 `io.netty.*` 460개 중 259개(56%)가 webflux 제거만으로 사라졌다. 나머지
201개는 `spring-boot-starter-data-redis`의 기본 드라이버 Lettuce(Netty 기반)가 이번
변경과 무관하게 항상 로드하는 몫이다(webflux 제거 전후로 `io.lettuce.*` 카운트가
241→227로 거의 그대로인 것과 일치). 즉 이번 조사 전에는 "Netty가 남아있는 이유"를
AWS SDK CloudWatch 클라이언트나 firebase-admin의 gRPC 전송 계층으로 추정했으나,
`io.grpc.*`/`software.amazon.awssdk.*`가 두 버전 모두 0개로 확인되며 그 추정은
틀렸음이 드러났다 — 실제로는 webflux 자체가 Lettuce보다 더 큰 Netty 클래스 로딩원
이었다.

## 남은 공백

- idle 부팅 스냅샷 1회 비교다. 실제 운영 트래픽 하에서 `WebClient`가 매 요청마다
  초기화하던 HTTP/1.1·HTTP/2 코덱, 커넥션 풀 관련 클래스는 idle 부팅만으로는 로드되지
  않으므로, 실제 절감폭은 이 219개보다 클 가능성이 높다.
- 두 버전 모두 자체 JVM 1회 부팅 측정이라 수십 개 수준의 클래스 로딩 순서 변동(JIT
  컴파일 스레드, GC 트리거 타이밍 등)이 섞여 있을 수 있다 — `io.lettuce.*`의 -14개
  차이가 그 예시로 보인다. `io.netty.*`/`reactor.netty.*`처럼 두 자릿수 이상 큰 폭으로
  일관되게 사라진 카테고리만 webflux 제거 효과로 귀속했다.
- 운영 배포 후 `jcmd VM.metaspace` 재측정(`../production/2026-08-04-운영-힙논힙-실측.md`와
  동일한 SSM+임시 JDK 컨테이너 부착 방식)으로 idle 한계를 보완할 예정.
