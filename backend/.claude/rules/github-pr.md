# PR 작성 규칙

이 저장소(모노레포 루트 `2026-capstone-26`)의 `.github/pull_request_template.md`가 실제
PR 템플릿이다. `backend/`는 이 루트 저장소의 하위 디렉터리이므로 GitHub이 PR을 만들 때 이
템플릿을 자동으로 채워준다.

## 병합 방식

기존 관례(일반 merge, squash 아님)를 유지한다. 커밋 이력을 보존하는 방식이므로,
PR에 올라가는 개별 커밋 메시지도 [git-commit.md](git-commit.md) 형식을 지켜야
merge 후 로그가 지저분해지지 않는다.

## 제목 형식

템플릿 자체는 제목을 강제하지 않는다. 브랜치명(`<type>/#<이슈번호>-<slug>`)과 연동되도록
다음 형식을 따른다:

```
<type> #<이슈번호>: <한국어 요약>
```

## 본문 구조 (실제 템플릿)

```markdown
## 🛰️ Issue Number

## 🪐 작업 내용

## 📚 추가 리팩토링 가능성
```

- **Issue Number**: 관련 이슈 번호(`#<번호>`)를 적는다. 템플릿 자체는 GitHub의 자동 종료
  키워드를 쓰지 않으므로, PR 병합과 동시에 이슈를 자동으로 닫고 싶으면 `closes #<번호>`처럼
  종료 키워드를 명시적으로 함께 적어야 한다. 이슈와 무관한 PR(잡일성 chore 등)이면 비워둔다.
- **작업 내용**: 무엇을 왜 바꿨는지, 리뷰어가 알아야 할 설계/구현 포인트를 bullet로 정리한다.
- **추가 리팩토링 가능성**: 이번 PR 범위 밖이지만 발견한 개선점을 남긴다. `.claude/CLAUDE.md`의
  "포트폴리오 관점 제안" 규칙과 같은 맥락 — 임의로 고치지 말고 여기에 적어 다음 작업으로
  넘긴다.
