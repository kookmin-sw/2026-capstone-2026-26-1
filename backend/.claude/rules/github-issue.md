# 이슈 작성 규칙

이 저장소(모노레포 루트 `2026-capstone-26`)의 `.github/ISSUE_TEMPLATE/이슈-템플릿.md`가
실제 이슈 템플릿이다. `backend/`는 이 루트 저장소의 하위 디렉터리이므로 GitHub이 이 템플릿을
그대로 적용한다. `.github/ISSUE_TEMPLATE/config.yml`에서 `blank_issues_enabled: false`로
설정되어 있어, 템플릿 없이 빈 이슈를 만드는 것 자체가 막혀 있다.

## 제목 형식

템플릿 자체는 제목을 강제하지 않는다(`title: ''`). 커밋 메시지·브랜치명과의 연동을 위해
다음 형식을 따른다:

```
<type>: <한국어 요약>
```

타입은 [git-commit.md](git-commit.md)의 커밋 타입 표를 그대로 따른다. 이슈 제목의
타입은 그 이슈에서 파생될 작업의 성격을 나타낸다 (예: 새 기능 이슈는 `feat`, 버그
리포트는 `fix`).

## 본문 구조 (실제 템플릿)

```markdown
## 📩 작업 이름

## 📜 TODO
- [ ]
```

- **작업 이름**: 이슈 제목과 중복되더라도, 무엇을 하는 작업인지 한 문장으로 다시 서술한다.
- **TODO**: 완료 조건을 체크리스트로 쪼갠다. 이슈를 닫을 수 있는 기준이 되도록 구체적으로
  작성한다(예: "API 구현", "단위 테스트 작성", "Swagger 문서 반영").

## 작성 톤 & 가독성

- 본문 서술은 음슴체(~함, ~임, ~됨)로 짧게 쓴다. "~합니다/~입니다" 같은 존댓말 평서문은
  쓰지 않는다.
- 한 문장이 길어지면 억지로 이어 쓰지 말고 `###` 하위 섹션이나 `-` bullet으로 쪼갠다.
- TODO 체크박스 하나에 여러 작업을 몰아넣지 말고, 검증 가능한 단위로 항목을 나눈다.

## 이슈 번호 연동

이 저장소는 커밋 메시지·브랜치명에서 이슈 번호를 `#<번호>`로 인용해 작업을 추적한다.
이슈를 새로 만들면 GitHub이 부여한 번호를 이후 커밋/브랜치/PR에서 일관되게 사용한다.
자세한 커밋·브랜치 형식은 [git-commit.md](git-commit.md), PR에서 이슈를 닫는 방법은
[github-pr.md](github-pr.md) 참고.
